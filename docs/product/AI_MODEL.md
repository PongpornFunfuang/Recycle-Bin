# AI model, evidence and limitations

Runtime: local FastAPI → PyTorch2.14.1+cu126/torchvision0.29.1+cu126 → Faster R-CNN ResNet50 FPN v2 COCO. CUDA diagnostic and actual inference passed on RTX3060 Laptop6GB. Manifest: `ml/manifests/active-model.json`; weights SHA256 `dd69338a24b8d7381807e247652bdc356325bcbaf1cd3e092e00e0a1a58706bf`. No training, new dataset or model download in this round. Torchvision architecture/package license is BSD-3-Clause; pretrained COCO objects are not a campus waste dataset, and dataset/image rights are separate. Test image attribution is `ml/test-images/ATTRIBUTION.md`.

The underlying detector has80 COCO object classes (91 metadata slots including background/N/A). The app supplies guide context for13 labels: bottle, cup, bowl and10 food labels. Paper, batteries and cans are guide-only; there is no corresponding dedicated COCO class. Positive class evidence in the small reviewed set is Bottle, not all13 context labels or all80 classes.

Photo pipeline validates byte count/type/magic, pixel dimensions, EXIF orientation and image decode; JPEG draft/thumbnail reduce input before tensor conversion. One inference is processed at a time; CUDA falls back to CPU if unavailable. Confidence threshold .25 retains low-confidence candidates; .50 accepts supported mapped objects. Unknown objects/unmapped classes, uncertain results and dark/possibly blurry images remain explicit. Neither threshold is a measured accuracy promise.

`docs/evidence/product/ai-evaluation.json` contains three actual runs per source image. Measured API pipeline time was372.92–682.34ms for the single bottle and379.04–393.56ms for the crowded bottle image in this run; HTTP roundtrip is recorded separately. These are local samples on this machine, not mobile FPS, thermal stability, network or worst-case latency guarantees.

Ground Truth: one manually reviewed, approximate normalized Bottle box on `empty-bottle.jpg`. At IoU≥.5, one accepted Bottle matched (best IoU≈.827), with TP1/FN0/FP0 **for this class on this one image only**. Other scene classes are not exhaustively annotated; no general precision/recall/mAP/accuracy is claimed. The crowded image is not exhaustively annotated, so numerical misses/false positives are Pending. Visual review does show a low-confidence Banana candidate on a scene of bottles; this is a known false label, not a valid food/material recommendation. Many small/occluded bottles remain hard to detect individually.

Photo/browser inference, synthetic continuous camera/snapshot and physical Chrome camera inference all passed their recorded local tests. Physical test completed3 successful requests, max concurrency1, closed tracks and issued no requests after stop; frames and labels were not retained. It does not certify recognition accuracy on that private scene or physical phone browsers. Real iOS/Android testing and sustained heat/RAM/VRAM measurements remain Pending.

Never infer plastic from Bottle, food waste from mere object presence, disposal from prediction, or bin color/location from a model class. The independent verified rule engine requires user material clarification and source-backed local data. Live overlays refer to the most recently processed frame; motion/network delay can make them lag. Snapshot re-inference aligns a saved result to the frozen bytes. A waste-specific evaluated dataset/fine-tuning program would be separate work with licenses, splits, annotations, mobile/GPU benchmarks and user approval.
