**Types/keys/indexes:** UUID identities, timestamptz event/audit times, normalized junction PKs, bounded integers/coordinates/confidence, JSONB for versioned contracts/snapshots, text arrays for steps. Composite owner FKs prevent associating B's detection/session with A's data; composite area FKs prevent linking a bin to another area's location/rule. Generated schema-catalog.json lists all211 columns,325 constraints,81 indexes and52 policies across37 RLS-enabled base tables. Counts describe the current local candidate, not hosted state.

**Transactions:** Each file has BEGIN/COMMIT. A failure rolls back only the current file, not earlier committed files. New save/confirmation/grading execute atomically; advisory transaction locks serialize same owner/event. Fault-injection tests show disposal and audit roll back together. Idempotency payload equality is strict: retries must reuse the same UUID/time/content. Changed content requires a new event, never silently overwrite an old one.

**RLS/grants:** anon gets only explicitly public references/published data/health. authenticated gets owner reads, restricted profile update, restricted feedback/contact columns, callable checked RPCs. Admin policies call private.is_admin; admin access is not derived from profile metadata. service_role can execute the scan writer and inherently bypasses RLS; the application uses it only after signature and getUser verification. Private answer keys/audits/roles are not readable directly by ordinary users. Keys are not sent in quiz GET; explanations can be returned after grading.

**Versioning:** Verified/retired rule contents cannot be edited in place; archive/status lifecycle changes are allowed while historical snapshots remain stable. The admin creates a new rule version within the same rule_key; link bins while Draft, then verify. Ambiguous active rules return Pending. Only unconditional or a single linked material_id condition is supported. Unknown condition shapes fail confirmation, including legacy records. Source expiry hides current recommendations; already confirmed snapshots remain readable to the owner.

**Idempotency of migrations:** These DDL files are deliberately not rerunnable.0005 explicitly refuses reapply;0001–0004 object collisions abort rather than pretend success. Keep an external approved migration ledger with filename/hash/time/operator/outcome; do not rerun a committed file. Local test reapply + explicit rollback confirms existing version record survives. Business event idempotency is separate from DDL idempotency.

**Preflight:** Verify target project and empty public/private namespaces or inspect existing objects/users/rows first. If data exists, stop the fresh-install sequence and prepare a reviewed incremental/backfill plan. Record exact file hashes and database export. Review grants/default privileges through the actual anon/authenticated API after migration; Supabase-managed defaults/extensions and PostgREST caching differ from PGlite. Reload schema cache through approved operator tooling if needed. Never disable RLS to make an API test pass.

**Rollback:** There is no destructive down migration. On error, stop, ROLLBACK the current open transaction and inspect committed ledger/schema before retry. For a used database prefer a reviewed forward fix. Restoring a separately verified export may lose subsequent writes and requires explicit approval and a maintenance window. Free Plan does not justify assuming point-in-time recovery exists. UI backup is not a DB backup. No rollback, Cloud SQL or Auth setting change was executed in this round.
